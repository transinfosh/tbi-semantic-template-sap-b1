### 已撤回 R01：人为缺失工单不能作为业务缺陷依据

原反例保留生产库存行、刻意不创建其来源 OWOR，只证明了缺失关联记录时 LEFT JOIN 的一般行为。没有现场记录或 SAP 正常业务规则证明这种输入可以发生，因此不足以把当前生产 View 判为缺陷。按用户反馈撤回 R01，不要求修改其工单键投影，两个生产 View 保持现状。后续合成场景应先满足 SAP 合法业务约束，再用于验证业务逻辑。

### R02：头日期可保留，行日期应另行提供

**状态：已修复源码与 P1 草稿，未发布。** 三个原头日期技术名、取值及顺序保留，显示名明确“凭证头”；新增三个行日期追加在末尾，原金额及分录粒度保持。以下为原审查证据，不表示修补后仍缺字段。

位置：[凭证行 SQL 第 5–7 行](workspace-views/sql/finance_journal_line_detail.sql#L5)。当前日期字段明确取头值，本审查**不判头日期本身错误**。缺口在于 View 粒度是凭证行，却没有提供独立行日期，无法直接选择两种业务口径。官方 [JDT1 表参考](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/JDT1.html) 定义行级日期；[单据设置帮助](https://help.sap.com/docs/SAP_BUSINESS_ONE/68a2e87fb29941b5bf959a184d9c6727/45071a63f61941dee10000000a1553f6.html) 明确在允许逐行修改时可设置不同过账日期，主代理已独立复核该依据。

合成场景的头日期为 9 月 30 日、一个分录行日期为 10 月 1 日。按现 View 日期筛选十月净额为 0，按行日期为 100。这证明两种口径不能互相替代；不据此认定按头日期统计的现有报表错误，也不把本 View 宣称为完整历史账龄。

### R03–R06：模型中确实缺失，源端与官方定义均存在

位置：[ITM1 价格](../models/itm1.json#L19)、[OITM 最近采购价格](../models/oitm.json#L217)、[OITM 有效期](../models/oitm.json#L453)、[OCRD](../models/ocrd.json)、[OCR1 成本中心键](../models/ocr1.json#L59)。主代理复核了当前保存模型与新读取的源结构；这些不是字段改名或仅界面未展示造成的误判。

价格角色据 [ITM1 官方参考](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/ITM1.html)；最近采购三元组及启停用期间据 [OITM 官方参考](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/OITM.html)、[OCRD 官方参考](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/OCRD.html)；成本中心直接键据 [OCR1](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/OCR1.html) 和 [OPRC](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/OPRC.html)。具体字段、类型、场景和最小验证要求见模型覆盖报告 G01–G04。

### R07：余额公式未判错，缺的是输出单位

位置：[批序列库位余额 SQL](workspace-views/sql/inventory_batch_serial_bin_current_balance.sql)、[批序列仓库余额 SQL](workspace-views/sql/inventory_batch_serial_warehouse_current_balance.sql)。两个 SQL 都没有连接 OITM 或输出单位，相邻物料总量 View 已提供 `current_inventory_unit`。建议补当前单位并验证左右连接不放大余额；不要将当前单位回填为历史交易单位。字段依据、缺主数据及异单位验证要求见模型覆盖报告 G05。

## 已知边界、可选补充与清理候选

1. **共享字典仍有空位。** OCTG 付款条件、OPLN 价目表、OSHP 运输方式目前均不在 P1；建议按名称查询需求补最小主数据与关系，归共享主数据。归共享不等于之前已加入，也不等于需引入完整定价或分期功能。
2. **预留发票反向来源关系仍待放行。** `DLN1(BaseType=13) → INV1`、`PDN1(BaseType=18) → PCH1` 已列在 [deferred.json](deferred.json#L330)。当前正式关系只支持另一方向的正常开票路径；没有订单来源的预留发票再发货／收货，无法仅靠现有正式关系完整追溯。合成场景已确认这个覆盖边界，但现场样例仍需补验。订单起点 View 不包含无订单单据是已声明范围，**不是本次新引入的 View 错误**。
3. **没有应立即删掉的确定冗余表。** 不建议因表号、行数少或分组位置删除 INV9/INV11 等已确认保留的表，也不建议删除新增四张库位表。字段方面可评估将本地化配置、维护日志、默认科目配置从普通展示中隐藏；证据尚不足以做破坏性删除。
4. **可直接整理的旧说明。** [ITM1.PriceList 第 34 行](../models/itm1.json#L34) 残留“1 为库存明细原 SQL 使用的价目表”，与本模型不默认价目表编号的约定冲突，宜去掉历史实现暗示。
5. **主键可空元数据。** 16 个源端 NOT NULL 的主键列在语义中仍标 `notNull=false`。当前主键声明完整，尚未证明造成计算错误，列为低优先级一致性修正；应同时检查生成链，避免改后被覆盖。
6. **常用 View 后续候选。** 未清订单、行交期及退货／贷项独立追溯可按常用问题扩展；已有原始模型不等于这些问题完全不支持。当前追溯不含可累计金额与数量是防止多对多重复的合理选择。

商机、拣货、草稿审批、定制收入、特殊价格扩展、框架协议和暂缓的分期功能均保持既定排除范围，不作为“缺表”扣项。生产仍通过 OIGE/IGE1 与 OIGN/IGN1 共享库存单据追溯，生产分组只有四张专属表不构成缺陷。
