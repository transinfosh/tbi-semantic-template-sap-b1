# 销售语义 BDD 场景

## SALE-FIELD-01：正式报价、备选方案与BOM层次

- Given 已确认报价同时有普通套件、组件、备选行和未知行类型，另有未确认报价。
- When 分析正式报价金额、备选方案或套件与组件数量。
- Then 可按 Confirmed、LineType、TreeType 分别确定问题范围；未知行不默认为普通行，不把备选方案强行相加，也不把父项与组件数量无差别合计。
- And 不新增适用于所有报表的默认过滤或由 TreeType 推导父子行键。

## SALE-FIELD-02：服务未清金额和预留发票物流状态

- Given 服务发票原金额200、贷项后保存未清150；另有已结但仓库未结的预留发票。
- When 读取服务行当前未清金额或待继续交货的预留发票。
- Then 使用服务行 OpenSum 三币保存值及其适用币种，不能用 OpenQty 代替金额；物流状态使用 InvntSttus，并与 isIns、DocStatus 分开。
- And 不将行未清金额称为现金到账、整单欠款或历史账龄，不从单一状态推断全部实际交货量。

## SALE-FIELD-03：头行项目与销售员分别归属

- Given 表头与行保存不同项目和销售员，另有空值、未匹配项目及当前已停用项目。
- When 按本行项目和销售员分析历史业务。
- Then 关系分别用本行 Project/SlpCode 连接 OPRJ/OSLP，头项目仍使用头 Project；保留空值、未匹配及已停用项目的事实行，不用头值或当前客户主数据替代。

## SALE-FIELD-04：抵扣净额、税额、含税额及三币

- Given 同一预付款抵扣有基础金额、已应用金额、明细净税拆分与不同币种保存值。
- When 按相应职责核对抵扣。
- Then 对每个金额职责使用其LC/FC/SC配套，不把净额与含税额相加当收入，不按当前汇率重算保存值；具体FC代码未确认时保持待核实。
- And INV9/RIN9保留两列复合键，INV11/RIN11保留LineSeq及LineType，不能连接全部物料行后重复累计。

## SALE-FIELD-05：共享列精简和版本兼容

- Given 物理表保留共享收款、分录、日期或库存标志列，精选层没有该对象上已确认的用途。
- When 应用本轮销售字段取舍。
- Then 当前消费者依赖检查通过后才移除；原SAP列和业务值不变，旧发布及历史图表版本保持冻结。
- And ORDR.CancelDate仍可查询且标为禁止发货截止日，RIN1.NoInvtryMv及适用应收/预付款结算字段保留。

## SALE-MCP-01：销售实体名称与父集合上下文

- Given 七类销售对象分别对应不同物理头行表。
- When 按 `Quotations` 等 Service Layer 实体名发现并读取模型。
- Then 能发现相应头行，行说明保留具体父对象的 `DocumentLines` 路径与物理表，不能仅凭共享 `DocumentLine` 类型合并不同单据。

## SALE-MCP-02：枚举表示与来源行号

- Given API 枚举名称、序号与数据库字符码不同，来源行号可以与数组位置不同。
- When 解释状态或连接来源行。
- Then `DocStatus/DocType` 分别保留数据库 `O/C`、`I/S`；不把 API 名称、序号或共享枚举其他成员当作本列 SQL 值，未知值保持待核实。
- And 来源使用已声明的 `BaseType/BaseEntry/BaseLine` 及真实 `LineNum`；不得使用显示单号、显示顺序或 API 数组下标代替。

## SALE-MCP-03：修改范围与冻结版本

- Given 销售组以外的模型和已发布版本已有各自定义。
- When 保存此次销售说明增补。
- Then 仅七对销售头行的描述变化；原有字段契约、关系、分组、其他模型及全局说明保持不变，历史发布继续冻结。

日期：2026-10-20。状态：销售模块第一轮整理；以下为预期行为，验证结果分级记录于测试映射。

本文件定义[规格契约](销售语义-规格契约.md)的预期行为，不记录已通过结论；实际方法与结果见[测试映射](销售语义-测试映射.md)。本轮补齐标准字段、维度关系和说明；涉及 Agent 回答的场景仍是独立验收目标，不表示新增了查询程序或已执行真实问答。

## SALE-DESC-01：字段描述提供额外业务信息

- Given 字段标题已经表达基本含义，如取消日期、客户名称。
- When 在模型编辑页浏览该字段。
- Then 描述可以留空，不重复英文标签和来源前缀。
- And 容易误用的字段通过描述说明业务角色和边界；`GrossBuyPr` 显示为“毛利计算基价”，不固定解释为实际采购成本或库存出库成本。
- And 本轮不改变技术字段、类型、关系或金额值，也不据此认定毛利币种与真实金额已验收。

## SALE-CUR-19：币种来源按说明层级保存

- Given 七张销售表头包含标准列 `CurSource`，公司本币与系统币可以不同。
- When 浏览模型、表和字段说明，或通过 describe 读取字段含义。
- Then 模型说明保留统一 LC/SC 来源，表说明保留三币金额和粒度职责，`CurSource` 字段说明完整列出 `L/S/C`。
- And `C` 表示业务伙伴币种，不能单凭它认定外币；实际币种读取 `DocCur`，本币和系统币代码统一从同一公司 `OADM` 获取。
- And 不按 `CurSource` 给所有金额列切换币种，不把行价格 `Currency` 当成金额列的通用币种。
- And 七个新增字段以外的查询结构、金额定义、分组和现有发布保持；草稿保存不改既有 Run 的语义快照。

## SALE-CUR-01：以 Git 模板确定销售范围

- Given 公共模板已有七对销售头行表和四张预付款抵扣附属表。
- When 盘点销售对象并准备模块整理。
- Then 以 Git 仓库中的模型定义确定本轮为 18 张已有表，不用某一工作区的额外对象扩大模板范围。
- And 不根据模板缺项删除实例对象；新增标准字段和维度关系有官方依据，目标实例采用前经过兼容验证、导入和独立发布。

## SALE-CUR-02：公司本币金额

- Given 一张外币销售单据，所属公司的本币与单据币种不同。
- When 解释 `DocTotal`、`PaidToDate` 或 `LineTotal`。
- Then 根据已核实的字段含义使用同一公司的 `OADM.MainCurncy`，分别说明合计、累计收付及不含税行金额的职责。
- And 不因为单据是外币单据就将上述列标为 `DocCur` 币种。

## SALE-CUR-03：系统币与本币不同

- Given 公司的 `MainCurncy` 与 `SysCurrncy` 不同。
- When 解释 `DocTotalSy`、`PaidSys` 或 `TotalSumSy`。
- Then 金额使用系统币标签，其币种来源为同一公司的 `OADM.SysCurrncy`。
- And 不把系统币写成本币，也不因两个样本数值相等而认为两列等价。

## SALE-CUR-04：单据外币金额

- Given 一张外币单据，适用外币列已有值。
- When 解释 `DocTotalFC` 或 `PaidFC`。
- Then 金额与所属单据 `DocCur` 成对使用，并保留单据合计与累计收付的区别。
- And 不将当前累计收付冒充指定历史期间的收款发生额。

## SALE-CUR-05：行价格币种与外币行金额

- Given 正常外币销售单据的行价格 `Currency` 与头 `DocCur` 不同。
- When 完善行价格与外币行金额说明。
- Then `Currency` 明确解释为行价格币种，不被推广为 `LineTotal` 或 `TotalSumSy` 的币种。
- And `TotalFrgn` 按头 `DocCur` 解释，并标明这是官方字段族与币种规则的组合解释，不假称 `RowTotalFC` 页面直接声明了该映射。
- And 保留目标样本待验证状态，不依赖数值相近推断，不据此新增自动单位绑定或换算公式。

## SALE-CUR-06：本币单据的外币列不适用

- Given 本币单据的有效本币金额非零，而对应 FC 列为零或不适用。
- When 回答该单据金额。
- Then 不把 FC 列的零解释为单据没有业务金额；按所问币种选择适用金额，外币口径不适用时明确说明。
- And 不把本币金额复制到外币列，也不静默给它贴上其他币种标签。

## SALE-CUR-07：真实零与缺失分别处理

- Given 一个适用金额列有真实零值，另一项金额或币种来源缺失。
- When 汇总或解释结果。
- Then 保留真实零值；缺失项保留未知或不完整状态，不自动补零。
- And 不把所有 FC 零值一概改为未知，适用性判断需要单据与币种上下文。

## SALE-CUR-08：不同外币不能直接合计

- Given 两张单据使用不同外币。
- When 用户要求汇总外币销售金额。
- Then 按币种分别汇总，或依据用户已明确的统一币种口径选择对应金额。
- And 未明确转换依据时，不无差别求和或使用当前汇率生成历史金额。

## SALE-CUR-09：表头金额连接多行

- Given 一张销售单据有多条明细。
- When 连接头行后统计单据金额。
- Then 单据头金额按单据键只计一次，行金额按行粒度计算。
- And 两种粒度不直接混加；测试须包含至少两行以检出重复累计。

## SALE-CUR-10：来源单据类型与行号

- Given 不同单据类型复用了相同内部编号，来源单据又有多条行。
- When 使用既有关系追溯销售来源。
- Then 同时保留声明的来源类型、内部单据键和内部行号条件。
- And 不仅按显示单号、物料编码或 `BaseEntry` 连接；本轮不新增待审来源边。

## SALE-CUR-11：贷项、取消与金额方向

- Given 数据同时包含发票、贷项和取消相关记录，且统计范围与方向规则已经明确。
- When 计算该范围的销售净额。
- Then 按明确规则处理单据角色与原始金额方向，保留可追溯的原值。
- And 不无条件 `ABS`、机械取负或双重取反；规则未明确时不能假称净额已确定。

## SALE-CUR-12：预付款不重复计入收入

- Given 一笔应收预付款已发生收款，并在最终发票中抵扣。
- When 解释销售、收款及抵扣金额。
- Then 分别展示原预付款、已收款、已抵扣和最终发票的职责。
- And 不把预付款金额与最终发票金额相加作为新增销售收入；过账、收款与抵扣状态分别判断。
- And `ODPI.DpmAmntFC/DpmApplFc` 的精确币种来源保留待核实，不从普通 `DocTotalFC` 自动继承已确认状态。

## SALE-CUR-13：抵扣附属表的不同粒度

- Given 一张发票有多条物料行、多笔抵扣记录及税额或舍入明细。
- When 读取 `INV9/INV11` 或 `RIN9/RIN11`。
- Then 分别遵循记录复合键，区分净额、含税额、基础额、已应用额和税额。
- And 不把抵扣记录行号当作物料行号，不与全部物料行连接后直接累计。
- And `INV9/RIN9.DrawnSumFc` 与四张附表的 `GrossFc` 逐字段核实具体币种来源；未确认前不直接指定为所属发票、贷项或来源预付款币种。

## SALE-CUR-14：历史金额与汇率方向

- Given 单据记录汇率与当前每日汇率不同，公司还配置了汇率方向和显示精度。
- When 解释原单据 LC/FC/SC 金额。
- Then 优先使用适用口径的已记录金额，换算说明结合字段定义及 `OADM.DirectRate`。
- And 不统一假定乘率或除率，不用当前汇率或显示舍入精度覆盖历史记账金额。

## SALE-CUR-15：公共字段不夹带客户口径

- Given 原字段说明包含“含税单价用于销售提成金额计算”。
- When 整理公共销售字段定义。
- Then 保留已核实的价格、税费、折扣、单位及币种含义，去除客户专用用途断言。
- And 不增加新的提成公式、固定币种、客户清单或默认业务筛选。

## SALE-CUR-16：模板升级不改变权限和历史冻结版本

- Given 工作区已经存在已发布版本、实例扩展与冻结 Run，而公共 Git 模板发生变化。
- When 通过正常 Git 差异预览、合并、导入和发布采用新模板。
- Then 保留实例扩展及权限，历史 Deployment 不被回填，原 Run 仍使用原冻结语义，新调用使用新激活版本。
- And 说明不授予跨工作区访问权，不取消强制过滤，也不把公共模板未包含的对象解释为实例应删除。

## SALE-CUR-17：税费三币配套与仍未覆盖字段

- Given 模板补齐七头的税额、折扣、费用、舍入及七行税额、含税行额的标准三币配套。
- When 用户要求这些金额的特定币种明细。
- Then 按字段职责及适用币种选择保存值，新增字段均须核对目标版本。
- And 毛利等仍未覆盖的字段明确标记缺口，不用任意其他金额或自行换算替代。

## SALE-CUR-18：真实问答验收独立记录

- Given 模板结构校验、字段说明断言或自造数据测试已经通过。
- When 判断销售语义是否能被真实 Agent 正确使用。
- Then 仍需记录真实模型调用、实际选用字段、冻结版本、查询结果与答案，覆盖不同币种和异常边界。
- And 在完成该验收前明确标记待验证，不将字符串断言或固定调用脚本作为真实 AI 行为已通过。

## SALE-CORE-01：七类单据的共享维度

- Given 七类单据的客户、单据销售员、编号系列，以及行物料、仓库和科目。
- When 解释维度或连接主数据。
- Then 使用各自已声明的键和基数；单据销售员不由客户当前销售员替代，系列同时匹配对象类型。
- And 缺少维度匹配的业务记录保持可见；科目匹配不证明该单据已过账。

## SALE-CORE-02：服务行和历史描述

- Given `DocType=S` 的服务单据行没有可匹配的 `ItemCode`，但保存了 `Dscription/AcctCode`。
- When 按单据查询业务明细并补充主数据。
- Then 仍返回服务行及历史描述、科目，不依赖物料主数据内连接。
- And 物料型单据的历史描述也不被当前物料名称无条件覆盖。

## SALE-CORE-03：分批交付与多个后续分支

- Given 一条订单行被分批交付，交货又分批开票并发生部分退货。
- When 统计交付、开票与退货数量。
- Then 按各分支的实际来源复合键独立聚合，再回连来源行；不能将两条开票与两条退货展开成四组计量。
- And 订单直接开票或无基础单据的记录分别保留，不强制经过交货。

## SALE-CORE-04：手工关闭与履约

- Given 订单或订单行已关闭，手工关闭标志可能是 `Y/N/U`。
- When 回答是否已全部交货。
- Then 手工关闭、当前开闭状态与实际交付事实分别解释，未知不改成未手工关闭。
- And 不将 `Quantity - OpenQty` 当作所有订单的实际交货量，也不把当前未清量当作历史余额。

## SALE-CORE-05：对象专属取消规则与库存影响

- Given 报价、订单、交货、退货、发票、贷项及预付款的取消枚举和工作流不同。
- When 解释取消或贷项的业务影响。
- Then 区分字典枚举与实际取消凭证流程，保留 `ORDR/ODPI` 的 `N/Y` 定义。
- And 贷项行的 `NoInvtryMv` 影响数量过账含义；不能把每张贷项的数量当作实物退货。

## SALE-STATE-01：有效值与界面状态分开

- Given 七张销售头的官方字段定义已分别核对。
- When 解释字段有效值。
- Then `DocStatus` 只解释 `O/C`，`CANCELED` 在订单和预付款为 `N/Y`，其余五头为 `N/Y/C`。
- And 界面的 Open–Printed、Draft 等显示不成为 `DocStatus` 的新增有效值；空值或未定义字符不自动改成正常状态。

## SALE-STATE-02：普通单据、被取消原单与取消单分别解释

- Given 一张支持生成取消单的发票已完成反向取消，另有普通未结、普通已结发票。
- When 组合解释 `CANCELED` 与 `DocStatus`。
- Then `N/O` 为普通未结，`N/C` 为普通已结，`Y/C` 为被取消原单，`C/C` 为新生成的反向取消单。
- And 两列中的 `C` 不混为一义；只用 `DocStatus=C` 不能判断取消，只用 `CANCELED<>Y` 不能排除取消单。
- And 两张反向取消相关单据均关闭的组合依据不自动推广为所有无新单对象的强制数据约束。

## SALE-STATE-03：不生成新取消单的对象

- Given 报价、订单或预付款请求使用标准取消操作。
- When 解释取消角色。
- Then 取消只处理原单，不另建反向取消单；原单的 `Y` 角色与开闭状态分别解释，不无依据宣判所有 `Y/O` 记录非法。
- And `OQUT` 字段列出 `C` 不证明标准报价会生成取消单；预付款发票不使用该取消操作。
- And 普通已结单仍是未取消角色；历史过账报表是否保留原单与取消单由其业务口径决定，不新增全局过滤。

## SALE-CORE-06：价格与税费保存值

- Given 一条销售行有行折扣、税额及含税行额，单据还有头折扣、费用与舍入。
- When 解释价格或合计。
- Then 区分折前税前 `PriceBefDi` 与折后含税 `PriceAfVAT`，带上行价格币种和历史计价单位。
- And 保留头行保存值，不重复扣折扣，不用一个简单算式替代所有历史税费及预付款处理。

## SALE-CORE-07：日期与应收职责

- Given 报价、订单和应收发票都包含 `DocDueDate`。
- When 用户分别询问报价有效期、预计交付日或付款到期日。
- Then 按对象选取其对应业务含义，不将所有日期都作为账龄到期日。
- And 当前累计已收金额不能直接回答任意期间收款发生额；历史应收与核销使用财务来源另行验证。

## SALE-CORE-08：预付款来源约束与待审关系

- Given 已审预付款抵扣关系与待审 `RIN9 → ODPI` 同时有字段提示。

- Then 已审关系保留各自 `ObjType` 或 `BaseType` 条件和抵扣复合键。
- And 未确认类型约束的关系保持待审，不仅凭 `BaseAbs` 或同一来源订单自动连接。

## SALE-EXPENSE-01：整单附加费用组成与粒度

- Given 一张发票有两条同类型运费和一条保险费，另一张不同币种发票使用尚未匹配的费用编码；贷项凭证可有同样的内部单据键。

- Then 费用记录按 DocEntry + LineNum 保留，不按 ExpnsCode去重；分别连到所属发票或贷项，未匹配类型仍保留，不跨币相加。
- And 费用不与整单物料行展开，也不重复累加表头总额；贷项原始金额不被无条件取负或取绝对值。

## SALE-EXPENSE-02：共享配置、草稿与发布范围
