# 财务凭证与项目维度规格契约

0.5.0范围为 `OJDT/JDT1` 凭证头行、`OACT` 科目、`OPRJ` 项目及共享 `OADM` 币种配置；0.8.0审查扩至收付款与内部核销，见文末补充。它承接财务模块第一轮整理，不宣称收付款、内部核销、历史账龄或所有财务报表已经验收。官方依据见[研究记录](finance-journal-research.md)；设计、实际实现和验证结果分别维护。

## 业务对象与稳定身份

| 对象 | 键与职责 |
| --- | --- |
| OJDT | `TransId` 内部主键；`Series+Number` 为另一唯一键，不能只以显示编号关联 |
| JDT1 | `TransId+Line_ID` 分录行键，0号行有效；发生额与当前未清余额分别保存 |
| OACT | `AcctCode` 内部主键；`FormatCode` 为分段展示码，`AcctName` 为当前主数据名称 |
| OPRJ | `PrjCode` 主键，名称不唯一；当前启用、锁定、有效期不作为历史事实的隐含过滤 |
| OADM | 同一公司本币与系统币配置来源，不与所有分录无条件展开连接 |

本轮保留上述技术身份和既有关系条件，纠正四个已声明主键列的 `notNull` 元数据，并补充头 `Ref1/Ref2/Ref3`、行 `Ref1/Ref2/Ref3Line` 六个标准参考字段。参考文本按数据库参考及目标源结构为200字符，允许空值，不是稳定关联键；不承诺旧DI API写入相同长度。

## 业务规则

- `Account→OACT.AcctCode` 解释本行总账或控制科目，并取得当前名称；`ShortName` 是业务伙伴或科目代码，不是科目名称。`ContraAct` 是对方账户标识，不保证完整多借多贷配对，也不自动建OACT关系。
- 头项目和行项目独立。行项目分析使用 `JDT1.Project`，不因头项目变更而回填；`PrjName` 仅作当前名称显示。同名代码不能合并；缺失、空项目、未匹配分别保留。需要保留未匹配事实时应使用适用的保留连接，不能把关系存在解释成运行时自动采用LEFT JOIN的保证。
- `ProfitCode/OcrCode2…5` 分别是维度1…5的分摊规则，不能直接当利润中心。完整分摊权重、有效期及多维规则不在本轮新增计算范围。
- `RealAcct` 为指数化标记，不用于区分资产负债与损益；`Postable` 区分可过账科目与标题科目，不能替代当前启用状态。`ActCurr=##` 是多币种配置值，不是真实货币单位。
- 借贷LC发生额由公司 `MainCurncy` 解释，SC由 `SysCurrncy` 解释，FC按本行 `FCCurrency` 解释。缺失外币标签不能猜成本币或系统币；不同外币分别汇总。科目当前币种配置和头币种不能无条件覆盖行币种。
- 保留已存金额正负号。负数原侧冲销与借贷对调都可能发生；不使用ABS或按DebCred、冲销标记二次翻号。借正贷负净额 `Debit-Credit` 只是一种明确代数口径，不自动变为收入、利润或现金流指标。
- 头金额在头粒度使用。头行连接后不得重复汇总LocTotal/FcTotal/SysTotal；头外币总额的全部多币适用性仍待核实。当前BalDue类余额不通过一个历史日期过滤就变为历史账龄。
- `RefDate/TaxDate/DueDate` 分别为过账、单据、到期日期；头行各自保存，不由创建日期或其他日期自动替代。`AutoStorno/StornoDate` 是反转设置，不证明已经执行；`StornoToTr` 方向及哨兵未核实，不新增默认自关联或统一取消过滤。
- 六个参考字段受参考字段映射配置影响，不能固定当发票号、客户订单号或分期号。`TransType=30` 表示Journal Entry来源类别，不证明由用户手工录入。

## 兼容、发布与未覆盖项

本轮仅调整标准字段说明、显示名、四个非空标记及六个新增参考列；不改源库表、不改既有类型/键/关系技术名，不增加View、Cube、客户公式、运行阶段或SAP专用执行分支。新增列须在目标数据库存在，非空标记须与源键一致；导入预览应展示变化，不能跳过实例差异合并。

Git模板和工作区独立维护。本轮按正常固定提交的Git预览、导入、引擎校验及语义/Knowledge配对发布至开发工作区；保留本地扩展、分组、权限、图表和历史Deployment，不自动改写其他客户现场。工作区验证不使公共模板成为客户财务对账结论。

查询截断、分页和“全部结果”承诺属于通用查询与交付契约，不能写成模型业务默认规则。旧运行发现的截断误述单独保留，本轮不以模型说明宣称它已修复。实际覆盖见[BDD](财务语义-BDD场景.md)及[测试映射](财务语义-测试映射.md)。

## 0.8.0 收付款与内部核销复核

收付款方式金额（现金/支票/信用卡/转账）与未指定单据挂账金额分别保留本币、外币、系统币；表头FC按DocCurr，应用行FC按目标单据适用币种，不能无条件共用一个币种标签。本币来自同公司OADM.MainCurncy，系统币来自OADM.SysCurrncy。转账日期、参考号和资金科目编码保留为本单记录，不把科目配置直接转成现金流类别。

应用行增加费用与舍入三币，核销费用增加外币/系统币；与实际应用额、现金折扣及预扣税分别解释，不新增一条通用对账恒等式。US1099 PaidSum不在当前默认精选；删除前检查依赖，原SumApplied/AppliedFC/AppliedSys保持。应用系统币精度改为DECIMAL(19,6)，科目名称扩容200字符；技术键、存储方向和源数据不改。

DocType中的C/S/A只是常用类别，地区P/T/D等不被自动重写。当前JDT1.ShortName同时承载BP/科目，既有OCRD路径仅在明确业务范围使用；未虚构类型过滤。支付子表DocNum到头DocEntry的四条父子边仍需要有判别力样例；资金科目多角色名称查询未验证，编码列保留而关系待审。已有TransId+TransRowId核销分录复合键保持，不简化为TransId。

兼容影响是候选字段新增、两处精选列移除与元数据修正，不改支付主键、原关系、权限或旧发布。本轮只保存草稿，不自动发布。来源与具体动作见[财务收付款研究](finance-payments-review-research.md)，技术和业务验收分层记录。
