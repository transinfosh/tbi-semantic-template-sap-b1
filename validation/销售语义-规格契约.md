# 销售语义规格契约

日期：2026-10-20。

状态：销售模块第一轮标准语义整理。此前已补核心三币说明；本轮补齐标准字段、维度关系与领域回归。预付款及抵扣附表的部分 FC 来源仍待核实，目标金额和真实问答尚未验收。实例导入发布结果单独记录，不由本文件推定。

配套文档：[BDD 场景](销售语义-BDD场景.md)、[测试映射](销售语义-测试映射.md)、[币种研究与证据边界](sales-currency-research.md)、[价格与税费研究](sales-amounts-research.md)、[流程与状态研究](sales-lifecycle-research.md)。模板通用边界沿用 [README](../README.md) 与 [来源说明](../source_notes.md)。

## 1. 功能范围与职责

本功能说明 SAP Business One 销售单据及预付款抵扣的范围、粒度、来源链路、日期、状态、数量、价格和三币金额。以公共模板现有 18 张销售表为审查对象，共享客户、物料、仓库、销售员、编号系列及公司币种定义。

本轮修正已有说明，并补齐官方已定义的字段与维度关系：销售退货和预付款的 `DocType/Series`、相关行的 `Dscription/AcctCode`，销售订单行 `LinManClsd`，七组头行的税额、折扣、费用、舍入及含税金额配套，以及行价格字段；具体集合以本轮来源记录和测试映射为准。增加 `ORDN/ODPI → OSLP/NNM1` 四条关系和七张销售行到 `OACT` 的科目关系，共十一条标准维度关系，保持既有直接营销来源边和待审特殊流程边界。

不新增主表、计算列、View、Cube 或默认销售指标，不改通用 Agent、工具协议和查询程序。模板由 Git 维护；指定实例经过差异预览、兼容校验和正常发布后采用新版本，保留实例扩展和历史冻结版本。实例验证不替代通用字段的官方依据，也不把客户数据写入公共仓库。

标准字段定义、币种来源和粒度属于语义模板。客户的销售提成、净销售统计范围、取消处理及其他专用口径由其工作区明确，不作为公共字段默认定义。权限、冻结版本、只读限制和查询预算继续由既有运行层执行，说明文本不能授予权限。

### 字段说明的表达

`0.6.2` 起，标题已能表达含义的字段（例如取消日期、客户名称）可不填写描述，不重复英文标签或来源前缀。描述用于补充业务角色、计算依据和容易误用的边界；来源统一在 `source_notes.md` 维护。

销售报价、订单、交货、应收发票和贷项行的 `GrossBuyPr` 统一显示为“毛利计算基价”。它用于计算毛利，可按设置来自价目表、最近采购价、物料成本等，不固定等于实际采购成本或库存出库成本。币种和计价单位仍须核验。兼容影响仅限显示标题和描述，技术名、字段类型、查询结构及已保存金额保持不变。

## 2. 销售表清单与本轮边界

以下以本 Git 仓库的模型定义为准，按 7 类单据及附属表列出 18 张表；这不是 SAP 全部销售表清单。工作区对象清单不作为模板覆盖范围的依据。

| 类别 | 表头 | 单据行 | 公共模板状态 |
| --- | --- | --- | --- |
| 销售报价 | `OQUT` | `QUT1` | 商机报价，不代表收入或库存移动 |
| 销售订单 | `ORDR` | `RDR1` | 客户需求及待履约量，关闭不等于实际交付 |
| 销售交货 | `ODLN` | `DLN1` | 交货及后续开票来源，与应收发票分开计量 |
| 销售退货 | `ORDN` | `RDN1` | 实物退货流程，不能直接代替贷项冲减 |
| 应收发票 | `OINV` | `INV1` | 两表均已有；预留发票另按已有 `isIns` 说明区分 |
| 应收贷项凭证 | `ORIN` | `RIN1` | 应收冲减；数量不一定对应实物退回 |
| 应收预付款 | `ODPI` | `DPI1` | 两表均已有；请求、发票、过账、收款和抵扣不得混为同一状态 |

| 附属表 | 职责与粒度 | 公共模板状态 |
| --- | --- | --- |
| `INV9` | 应收发票预付款抵扣，键为 `DocEntry + LineNum` | 已有，本轮补已有金额说明 |
| `INV11` | 应收发票抵扣税额及舍入明细，键为 `DocEntry + LineNum + LineSeq` | 已有，本轮补已有金额说明 |
| `RIN9` | 应收贷项预付款抵扣，键为 `DocEntry + LineNum` | 已有，本轮补已有金额说明 |
| `RIN11` | 应收贷项抵扣税额及舍入明细，键为 `DocEntry + LineNum + LineSeq` | 已有，本轮补已有金额说明 |

销售模型为 7 对头行表加 4 张抵扣附属表，共 18 张。共享 `OADM` 是币种配置来源，不计入这 18 张销售事实表。工作区与模板同步时另行比较差异；工作区的额外对象既不自动成为模板范围，也不因模板未包含就自动删除。

### 本轮行为与验证要求

- 每个头行关系保留单据键；直接营销来源同时匹配 `BaseType/BaseEntry/BaseLine`，支持跳过订单或交货的标准来源路径，不强迫每张发票经过同一条流程。
- 一行可以被分批交付、分批开票或部分退货。不同后续分支先在各自粒度汇总再合并，避免多分支连接放大数量或金额；`Quantity - OpenQty` 不作为实际交货量的通用公式。
- 物料与服务单据用表头 `DocType` 区分；保存的 `Dscription` 解释历史行，不要求服务行一定有 `ItemCode`。缺少物料、仓库或销售员的记录不能因内连接而静默丢失。
- 行 `AcctCode` 对应共享科目 `OACT.AcctCode`；该关系解释所选科目，不能证明报价、订单或其他非过账状态已经生成会计分录。实际过账与核销仍按财务来源核对。
- 订单手工关闭与履约分别解释；`DocManClsd` 是头标志，`LinManClsd` 是行标志，未知值不能补成“未手工关闭”。
- 取消枚举逐表核对。官方字段字典与实际取消流程分别说明，不能因为字段枚举包含 `C` 就推断所有对象都能创建取消凭证。
- 金额只使用适用币种的保存字段。税额、单据折扣、费用、舍入、行折扣和含税行额分别解释，不以一条未经核实的总额公式覆盖预付款、本地化和特殊税务处理。
- 验证覆盖官方字段与类型、全部直接来源边、头行与抵扣粒度、部分交付和分支防重复；实例物理列兼容、引擎校验与真实问答分开记录。

LC、SC、FC 分别表示公司本币、系统币、外币口径；它们不是三个固定币种名称。系统币可能等于或不同于本币。单据币种与行价格币种也不能被当作每个金额列的通用标签。

官方依据维护在币种研究、来源说明及来源记录中；本轮尚未确认的项保留上述状态，不以其他任务的已通过记录替代。此次组合解释只用于说明补全，不新增运行时单位绑定、换算公式或自动报表；需要这些能力时，先完成价格币种不同于单据币种的目标样本核对。

## 4. 关键行为约束

1. **金额与币种成对解释。** 使用金额字段时说明其粒度、税费口径和适用币种来源；本币、系统币、单据币种和行价格币种不互相替代。
2. **外币列存在适用性。** 本币单据的 FC 列可能不适用。该列为零不能推出整张单据没有业务金额，也不能直接改读另一金额后仍标为外币。反过来，适用口径下的真实零值仍是零；缺失值不能补成已确认的零。
3. **跨币汇总保留边界。** 不同单据外币金额按币种分别汇总，或在已经明确的统一币种口径下读取对应金额。不能无差别相加，也不从列名或相邻值猜币种。
4. **使用记录金额，不默认重算历史。** 单据金额、单据汇率与每日汇率资料分开；汇率方向结合 `OADM.DirectRate` 和字段定义解释，不统一假定乘或除。当前汇率、显示精度不能覆盖历史记账金额。
5. **头行与来源粒度保持。** 头金额按 `DocEntry` 计量；行按 `DocEntry + LineNum` 计量。连接明细后不得重复汇总表头金额；来源行连接沿用已声明的 `BaseType + BaseEntry + BaseLine` 条件。
6. **贷项与取消保留方向。** 不能无条件 `ABS`、机械取负或双重取反。净销售等统计须先明确单据角色、取消范围和符号约定，保留原始金额以便核对。
7. **预付款与收入区分。** 预付款金额、已收款、已抵扣和最终发票金额分别计量；预付款不作为一笔额外销售收入再次计入。抵扣表不与整张单据的所有物料行直接连接后求和。
8. **公共模板保持通用。** 含税单价的定义不附带“用于销售提成”等客户口径；不引入提成计算、默认客户、固定币种或客户专用筛选。

### 4.1 流程、状态和日期

直接来源由实际 `BaseType/BaseEntry/BaseLine` 决定。模板已有 11 条销售营销单据来源路径，包括报价直接交货/开票、订单直接开票、交货开票/退货、发票或退货生成贷项，以及报价/订单生成预付款。无基础单据的记录保留，不强行补一个来源。

`DocStatus/LineStatus` 表示当前开闭状态，`OpenQty` 表示当前未清数量。订单 `DocManClsd` 与订单行 `LinManClsd` 单独表示手工关闭，`U` 保留未知；据此不能推出实际交付、开票或历史时点未清数量。部分交付、开票和退货以对应后续单据事实汇总，多个分支不能直接展开相乘。

`0.6.3` 逐表确认七张销售头的 `DocStatus` 只有 `O=未结`、`C=已结`；界面的 Open–Printed、Draft 等综合显示不是该字段的额外编码。`CANCELED` 在 `ORDR/ODPI` 只有 `N/Y`，在 `OQUT/ODLN/ORDN/OINV/ORIN` 为 `N/Y/C`：`N` 表示未取消，`Y` 表示被取消原单，`C` 表示新生成的取消单据。完整来源见[流程研究第8节](sales-lifecycle-research.md#8-2026-10-21-补充取消角色与-docstatus-的组合)。

两列应组合解释，字段中的两个 `C` 含义不同：

| CANCELED | DocStatus | 组合含义 |
| --- | --- | --- |
| N | O | 未取消、未结的普通单据 |
| N | C | 未取消、已结的普通单据；已结不等于取消、已交齐或已收齐 |
| Y | C | 已取消且关闭的原单；生成反向取消单的流程完成后原单为此角色 |
| C | C | 已关闭的新取消单；用于反向冲回原单影响 |

后两行来自字段枚举与官方“原单、取消单均关闭”流程的组合推导，针对交货、退货、应收发票（含预留发票）和贷项。报价、订单、预付款请求取消时不生成新取消单，预付款发票不适用该取消操作。不能据上述双单关闭流程强制推断所有报价等无新单对象的取消记录均为 `Y/C`，也不能据此将 `Y/O` 一律判为非法；`CANCELED=Y` 仍表示已取消，开闭状态另按实际值解释。`OQUT` 字段虽列 `C`，标准报价取消仍不生成该角色。

查询未取消的普通单据可用 `CANCELED='N'`，其中包括普通未结与普通已结；如只需未结，再加 `DocStatus='O'`。`CANCELED<>'Y'` 会保留支持该角色的反向取消单，`DocStatus='C'` 会混合普通已结、被取消原单与取消单。历史过账及反向冲回的报表可能需要保留不同期间的原单与取消单，不能把只取 `N` 设为所有报表的通用过滤或硬编码净额符号。

本轮兼容影响仅限14处描述更新；未改变字段技术名、类型、有效值存储、接口、权限或默认查询，也未新增数据库枚举或交叉状态约束。真实取消状态迁移、历史数据合法性及SAP报表对账与本轮官方定义核对分别验收。

`DocDate`、`TaxDate`、`CreateDate` 与 `DocDueDate` 分开使用。报价的 `DocDueDate` 表示有效截止日期，订单表示预计交付日期，应收发票表示付款到期日期；其他对象只按其明确字段定义解释，不能统一标为账龄到期日。

### 4.2 主数据、服务行与结算边界

单据销售员使用单据 `SlpCode`；客户主数据上的当前销售员不是其历史替代。编号系列同时匹配 `Series` 与单据对象类型，显示单号不能作为跨类型单据的唯一键。物料名称优先保留行 `Dscription` 的历史事实；服务型单据 `DocType=S` 可以没有物料匹配，查询须保留这些行。

`AcctCode → OACT` 仅解释选用科目。实际会计分录、收付款发生额和内部核销由财务模块负责，累计已收金额不代表任意历史期间的收款发生额，也不能独立重建历史账龄。销售领域保留表间引用和金额职责，不在本轮生成财务余额公式。

`INV9` 到预付款、`INV11/RIN11` 的已审来源关系按各自类型字段使用。`RIN9.BaseAbs` 的官方相关表提示和实际 `ObjType` 约束仍需共同核实；既有待审 `RIN9 → ODPI` 不因文字提及而转为可用关系。退货后再交货等特殊路径也继续列于 [deferred.json](deferred.json)。

## 5. 兼容、权限与发布影响

本轮为已有销售对象增加标准字段和十一条维度关系，修正显示名与说明；保留已有技术名、字段类型、主键、直接来源条件和查询接口。新增字段要求目标数据库确实存在相应标准列；不兼容的目标版本应在实例适配时显式处理，不能静默导入不存在的字段。没有修改源数据库表结构，也不需要 Frappe schema 迁移。新模型内容会产生新的 MDL 摘要，这是正常版本变化，不修改历史 Deployment 或既有回执。

Git 模板仅是候选来源。已有工作区不随模板文件修改自动同步；后续导入与发布应使用明确目标、预览差异并保留实例独立性。当前冻结 Run 仍使用原 Deployment。任何描述补全都不绕过现有工作区授权、强制过滤、冻结身份或数据源权限。
