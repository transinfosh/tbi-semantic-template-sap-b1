## 1. 功能范围与职责

本功能说明 SAP Business One 销售单据及预付款抵扣的粒度、核心金额币种与来源。此次补全公共模板现有 18 张销售表的核心三币金额说明，并补充共享 `OADM` 的公司本币、系统币与汇率方向说明。

本轮只完善已有模型及字段的标题和说明。不新增表、字段、计算列、关系、View、Cube 或指标；不改通用 Agent、工具协议和查询程序；不导入、发布或回填任何工作区。公共模板与工作区实例独立演进，模板更新不能证明实例已经获得相同说明。

标准字段定义、币种来源和粒度属于语义模板。客户的销售提成、净销售统计范围、取消处理及其他专用口径由其工作区明确，不作为公共字段默认定义。权限、冻结版本、只读限制和查询预算继续由既有运行层执行，说明文本不能授予权限。

- 七组销售行表已有 `LineTotal/TotalFrgn/TotalSumSy`、`Price/Currency`。
- `ODPI` 已有预付款金额 `DpmAmnt/DpmAmntFC/DpmAmntSC` 与已应用金额 `DpmAppl/DpmApplFc/DpmApplSc`。
- `INV9/RIN9` 已有 `DrawnSum/DrawnSumFc/DrawnSumSc`；四张抵扣表均已有 `Gross/GrossFc/GrossSc`。其他已应用、基础金额及税额按各表实际字段解释，不假定它们已具备完整三币配套。
- 共享 `OADM` 已有 `MainCurncy`、`SysCurrncy`、`DirectRate`；币种代码应来自适用公司配置，不能写成固定币种。

上述是本地模板字段盘点，不代表金额来源、目标数据库兼容性或真实业务金额已经完成验收。

以下依据[币种研究](sales-currency-research.md)区分官方直接定义、多个官方来源的组合解释和待核实项。研究以 `OINV/INV1` 为字段级样本；向其他已有销售模型传播时仍须逐表确认字段存在、拼写及职责，不能把字段后缀当作唯一证据，也不宣称所有目标版本均已验证。

| 字段组 | 金额口径与币种来源 | 本轮证据状态 |
| --- | --- | --- |
| 表头 `DocTotal`、`PaidToDate`；行 `LineTotal` | 公司本币金额，币种代码来自同一公司 `OADM.MainCurncy`；单据合计、累计收付和不含税行金额分别解释 | LC 角色采用字段族与币种规则的组合解释；配置来源有直接依据；模板说明传递已核对，目标数据待验证 |
| 表头 `DocTotalSy`、`PaidSys`；行 `TotalSumSy` | 系统币金额，币种代码来自同一公司 `OADM.SysCurrncy` | SC 字段族与配置来源有直接依据；模板说明传递已核对，目标数据待验证 |
| 表头 `DocTotalFC`、`PaidFC` | 正常外币销售单据的外币金额，结合所属单据 `DocCur` 解释币种及适用性 | FC 字段族有直接依据；币种来源采用组合解释；目标数据待验证 |
| 行 `TotalFrgn` | 正常外币销售单据的外币行金额，按所属表头 `DocCur` 解释；行价格 `Currency` 不作为该金额的通用币种来源 | `RowTotalFC` 直接定义外币行总额；指向头 `DocCur` 是组合解释，不是该页面直接声明；价格币种不同的目标样本待验证 |
| 行 `Price`、`PriceBefDi`、`PriceAfVAT` 等已有价格字段及 `Currency` | `Currency` 是行价格币种；金额与价格、税前与含税、折前与折后分别说明，不能把价格币种推广给所有行金额 | 行价格币种有直接依据；其他价格字段逐项核实，不新增未有字段 |
| `ODPI` 的 `DpmAmnt*`、`DpmAppl*` | 分别保留原预付款金额与已应用金额，再区分已有 LC/FC/SC；不可用其中一组代替收款或收入 | `DpmAmntFC/DpmApplFc` 的精确币种来源尚未确认，不能从 `DocTotalFC` 自动继承 |
| 抵扣表的 `DrawnSum*`、`Gross*` 及其他已有金额 | 保留净额、含税额、基础金额、已应用金额和税额的不同职责；LC/SC 对应同一公司配置，不套用物料行粒度 | `INV9/RIN9.DrawnSumFc` 与四张附表 `GrossFc` 的具体币种来源仍待逐字段核实，不预先指定为所属单据或来源预付款币种 |

LC、SC、FC 分别表示公司本币、系统币、外币口径；它们不是三个固定币种名称。系统币可能等于或不同于本币。单据币种与行价格币种也不能被当作每个金额列的通用标签。

官方依据维护在币种研究、来源说明及来源记录中；本轮尚未确认的项保留上述状态，不以其他任务的已通过记录替代。此次组合解释只用于说明补全，不新增运行时单位绑定、换算公式或自动报表；需要这些能力时，先完成价格币种不同于单据币种的目标样本核对。

## 4. 关键行为约束

1. **金额与币种成对解释。** 使用金额字段时说明其粒度、税费口径和适用币种来源；本币、系统币、单据币种和行价格币种不互相替代。
2. **外币列存在适用性。** 本币单据的 FC 列可能不适用。该列为零不能推出整张单据没有业务金额，也不能直接改读另一金额后仍标为外币。反过来，适用口径下的真实零值仍是零；缺失值不能补成已确认的零。
3. **跨币汇总保留边界。** 不同单据外币金额按币种分别汇总，或在已经明确的统一币种口径下读取对应金额。不能无差别相加，也不从列名或相邻值猜币种。
4. **使用记录金额，不默认重算历史。** 单据金额、单据汇率与每日汇率资料分开；汇率方向结合 `OADM.DirectRate` 和字段定义解释，不统一假定乘或除。当前汇率、显示精度不能覆盖历史记账金额。
5. **头行与来源粒度保持。** 头金额按 `DocEntry` 计量；行按 `DocEntry + LineNum` 计量。连接明细后不得重复汇总表头金额；来源行连接沿用已声明的 `BaseType + BaseEntry + BaseLine` 条件。
6. **贷项与取消保留方向。** 不能无条件 `ABS`、机械取负或双重取反。净销售等统计须先明确单据角色、取消范围和符号约定，保留原始金额以便核对。
7. **预付款与收入区分。** 预付款金额、已收款、已抵扣和最终发票金额分别计量；预付款不作为一笔额外销售收入再次计入。抵扣表不与整张单据的所有物料行直接连接后求和。
8. **公共模板保持通用。** 含税单价的定义不附带“用于销售提成”等客户口径；本轮只修说明，不引入提成计算、默认客户、固定币种或客户专用筛选。

## 5. 兼容、权限与发布影响

本轮修改部分中文显示名，例如 `DocTotal` 显示为“单据总额（本币）”、`LineTotal` 显示为“不含税行金额（本币）”，抵扣附表将“本位币”统一为“本币”；新语义版本使用这些显示名和补全说明。本轮不改变模型技术名、字段名、类型、主键、关系条件或查询接口；不需要数据库 schema 迁移。显示名与说明变化会改变未来组装 MDL 的内容及摘要，这是正常的新版本内容变化，不修改历史 Deployment 或既有回执。

Git 模板仅是候选来源。已有工作区不随模板文件修改自动同步；后续导入与发布应使用明确目标、预览差异并保留实例独立性。当前冻结 Run 仍使用原 Deployment。任何描述补全都不绕过现有工作区授权、强制过滤、冻结身份或数据源权限。
