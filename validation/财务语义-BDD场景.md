# 财务凭证与项目维度BDD场景

以下是预期行为，不表示每个目标账套均已通过。范围与未覆盖项见[规格契约](财务语义-规格契约.md)。

| 编号 | Given / When | Then |
| --- | --- | --- |
| FIN01 | 同一凭证有多行、不同凭证都有0号行 | 用TransId+Line_ID保持独立，不丢0号行，不按Line_ID单列合并 |
| FIN02 | 不同系列显示编号相同 | 用TransId关联，显示编号按Series+Number区分 |
| FIN03 | BP分录的ShortName不是科目内部代码，内部码也不同于FormatCode | 沿Account→AcctCode取名称，不用ShortName或展示码替代关联 |
| FIN04 | 头行项目不同、同名不同代码项目 | 按所问粒度筛选；不回填、不按名称合并 |
| FIN05 | 行项目为空、未匹配或当前停用 | 保留所需事实与源值，不自动加当前状态/日期过滤；说明连接保留的要求 |
| FIN06 | 头金额连接多个分录行 | 不重复累计头金额；按事实粒度独立聚合 |
| FIN07 | 原侧负金额冲销或借贷对调冲销 | 保留存储符号，在明确日期范围用原始借贷金额计算，不二次翻号 |
| FIN08 | 多种行外币、空外币标签、科目币种为## | 分币种保留缺失标签，不把##或公司币种当行外币标签 |
| FIN09 | 凭证参考文本超过旧API文案长度或相同文本用于多行 | 六个字段保存数据库200字符定义，允许空值，不作为键或固定业务编号 |
| FIN10 | 分摊规则、RealAcct与科目状态用于解释 | 不把分摊规则当中心，不把RealAcct当报表科目分类，不把Postable当启用状态 |
| FIN11 | 头行日期不同、反转日期已设置但尚未执行 | 区分日期角色与反转设置，不直接推出已冲销或历史余额 |
| FIN12 | 从Git更新已有工作区并再次预览 | 本地扩展、权限、分组、资产及历史版本保留，重复导入差异为零；正常完成发布配对 |

| FIN13 | 收付款方式、挂账和发票应用各有不同币种及金额 | 按各自粒度和适用币种分别使用，不把方式金额和应用金额重复相加 |
| FIN14 | 目标应用有费用、舍入、折扣、预扣税和部分付款 | 读取保存的配套字段，不用单一未经核实的公式强行对齐 |
| FIN15 | 支付父子键和资金科目角色尚无验收样例 | 保持待审边界，不凭同名或简单复制启用关系；新增编码不等于角色查询已验收 |
| FIN16 | 删除US1099精选字段并保存新草稿 | 先检查依赖，保留原始物理列、现有消费者和冻结发布 |
