# 常用查询视图实施与验证

2026-10-22，首批16个查询视图已通过原生保存应用到 P1 草稿。当前草稿为 **109张表、3,244个表字段、408条关系、16个视图及320个视图字段**，分析模型仍为0。当前发布仍是 V18，原部署 `031tv4p8o5` 保持。

## 已应用范围

| 业务用途 | 视图 |
| --- | --- |
| 销售订单到收款、交货批序列 | 销售订单到收款追溯、销售交货批次序列明细 |
| 采购订单到付款 | 采购订单到付款追溯 |
| 收付款与发票当前状态 | 应收发票收款应用明细、应付发票付款应用明细、应收发票当前账面未结、应付发票当前账面未结 |
| 生产 | 生产发料明细、生产收货明细 |
| 库存 | 库存收发批次序列明细、库存收发批次库位流水、物料库位当前库存、批次序列库位当前库存、批次序列仓库当前库存、物料仓库当前库存 |
| 财务凭证 | 财务凭证分录明细 |

新增底表为 OBTL、OIBQ、OBBQ、OSBQ，共23个标准字段、14条直接关系。其主键和字段在目标源结构中已核对；客户自定义字段没有加入该扩展。完整 SQL、技术名称、字段标题及粒度见[扩展定义](workspace-views/README.md)和[清单](workspace-views/pack.json)。本轮不把扩展直接提升为公共模板默认导入；默认0.8.0仍为101表、370关系。

订单追溯同时覆盖先物流后开票、直接开票、预留发票后物流，保留未发生的后继、同物料多行及取消状态。追溯只承载身份、日期和状态；收付款应用独立保持应用行，避免跨订单、商品行和多次付款导致金额膨胀。当前账面差额、实际付款应用和现金收付是不同指标，没有新增订单级现金分摊规则。

批序列库存影响限定 StockEff=1，库位事务按原 OBTL.AbsEntry 保存分配组合；当前物料总量与批序列分量分开。原始数量和取消/冲销角色保留，不统一 ABS 或二次变号。生产沿共享库存单据和 BaseType=202，退回或拆卸组件不当作成品产量。

| 原生保存与发现 | 全105表基线加扩展在可丢弃站点正常保存并回滚；16视图320字段无UNKNOWN，业务标题齐全；目录能按订单到收款、批次、库位、生产发料及分录发现视图，结构化查询编译通过，describe不暴露实现SQL |

| 保护范围 | 原105张表文档、394条关系、50图表、15仪表板、7分组、原图表/仪表板版本及语义修订、全部20份部署和5份Knowledge记录保持，当前发布与工作区说明保持 |

新增对象通过既有治理机制产生自己的修订；没有覆盖原修订。SQL与定义是本地文件，未推送远端仓库。通用类型推断没有DocType/schema变化，不执行迁移；没有给Agent添加SAP专用规划规则。

## 仍待业务验收

- 目标库的3个库位视图及2个生产视图目前为空；结构、执行和自造数据验证通过，不表示真实库位分配、生产退料/拆卸或符号已对账。
- 最新收款38行、付款200行的父内部键与显示编号均相同，不能区分候选父键。实现采用官方对象归属、父主键与显示编号复合索引的组合依据，异号场景通过自造数据，但没有宣称真实异号样本已验证。依据见[单据链研究](document-chain-view-research.md)。
- 交货批次视图明确以日志Doc角色和StockEff=1定位，未把仅Apply匹配的特殊路径推定为已验证实际交货；预留、退货、取消和不同日志动作需按目标业务核对。
- 未完成SAP界面/标准报表全量对账，未重放真实自然语言Agent问题。P1新视图仍在草稿，正常发布后才进入新的冻结查询目录，当前V18不包含这些新增对象。
