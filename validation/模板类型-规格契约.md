# 模板类型规格契约

日期：2026-10-22。版本：0.8.3 本地候选已实现，离线验证通过。适用公共模板及仓库附带的可选工作区扩展；不自动导入、修改源库或发布工作区。

## 类型与来源资料

- MDL 的字段 `type` 只使用 tBI 支持的大写基础标量类型，例如 `VARCHAR`、`CHAR`、`DECIMAL`、`INTEGER`、`TIMESTAMP`。不混入长度/精度，不合并整数与小数类型，不通过重写 SQL 获得一致性。
- 公共模型原有逐列类型标注完整移入 `reference-contract.json` 各表的 `source_types`；该文件继续维护官方来源和列名。可选扩展的原始标注单独保存在 `workspace-views/source-field-types.json`，不将扩展表纳入默认导入。
- `VARCHAR(96)` 保留长度 96，`DECIMAL(19,6)` 保留总精度 19、小数位数 6；原标注不带参数时原样记录，不假定缺失参数。保存的是修订前模板的来源类型标注，可能采用可移植表达，并非本轮重新读取的目标库 DDL，也不将 VARCHAR 标注当作已经确认的源库 nvarchar/char 类型。
- 构建检查字段类型属于基础类型目录，来源类型记录存在、格式可解析且基础类型一致；不在构建时静默修正源码。来源类型记录只用于校验，不进入导出的 MDL，不覆盖真实源列或增加 DocType 字段。
- 新增字段时同步记录来源类型及官方依据；长度/精度发生变化只更新来源校验记录，仍需目标公司库核验。不能单靠模板自洽证明实际源类型正确。

## SQL 与兼容边界

只修改类型标注和相关校验资料；所有 SQL 文件、语句和表达式逐字保持，包括 `CAST(... AS DECIMAL(19,6))`、字符串长度转换、标识和字面量。SQL 转换参数影响实际计算，不能按类型标注规则删除。

模型/字段名、顺序、说明、精度相关业务限制、主键、关系、分组和语言包保持。此前 PaidSum 字段族新增及不等同 PaidToDate 的规则保留，19,6 移到来源记录中，未清应付公式仍不新增。

清单版本从本地候选 0.8.2 增至 0.8.3；模型数、字段数、关系数保持。tBI 现有导入器已对标量类型规范化，因此预期仅长度参数差异不会造成新的语义类型冲突；本轮以离线对比验证此点，不宣称已执行真实工作区导入。已保存记录、Deployment 和历史验证快照不改写，新导出 MDL 摘要会变化，仍由使用方预览并按正常流程发布。

## 验证与证据

配套[BDD](模板类型-BDD场景.md)和[测试映射](模板类型-测试映射.md)。需要全包基础类型/来源覆盖检查、错误类型与缺失来源负例、长度/精度保留、SQL CAST 保持、幂等与完整既有回归。无需 Bench schema 迁移，本轮不访问客户库。
