# SAP Business One 语义模型模板

本仓库维护可复用的 **SAP Business One 10.0 / SQL Server 语义模板**。tBI 从 Git 中读取 `template.json`，按其中的 `sources` 声明读取模型和关系文件，在服务端组装 MDL；导入后由工作区独立维护实际模型。Git 不保存工作区实例、数据库连接或客户业务数据，也不提交重复的完整 MDL 产物。

当前使用 `main` 分支维护和导入，本地候选清单版本为 `0.8.3`，本次修订不创建Git标签。覆盖销售、采购、库存、生产和财务的 **101个表模型、3,107个字段、372条关系**。它采用MDL `layoutVersion: 4`，不代表覆盖SAP全部表，也不表示所有公司库已完成业务金额验收。本地候选不代表远端分支已经更新。

## 在 tBI 中使用

1. 在工作区的 Git 导入入口选择本仓库或填写仓库地址，分支填写 `main`，清单路径填写 `template.json`。
2. 检查目标工作区、数据源与物理 schema。模板物理表统一使用 `dbo`，未指定公司数据库；逻辑 catalog `sap_b1` 不是实际公司库名。
3. 预览模型变更和校验结果后导入。导入仅更新该工作区的模型，发布仍由工作区单独执行。
4. 记录导入所解析的提交 SHA。分支后续更新不会自动改变已导入模型，切换分支后需要重新预览和导入。

当前模板尚无 Views、Cubes 或客户专用指标定义，避免将某个项目的价格表选择、金额口径和业务筛选当作通用默认。`views/` 和 `cubes/` 已作为预留目录在清单中声明，使用 `.gitkeep` 保留空目录；占位文件不参与导入。对已有工作区导入前，应检查覆盖范围并保留客户修改；具体冲突处理以 tBI 的导入预览为准。

## 目录和构建

| 路径 | 用途 |
| --- | --- |
| `template.json` | 导入入口：模板标识、版本、MDL 元数据、源目录和兼容要求 |
| `groups.json` | 七个业务分组的编码与显示名称 |
| `models/<name>.json` | 每个标准表的字段、主键、说明及group归属 |
| `relationships/<name>.json` | 每条关系的条件和基数 |
| `views/` | 视图定义的预留目录，目前仅含 `.gitkeep` |
| `cubes/` | 分析模型定义的预留目录，目前仅含 `.gitkeep` |
| `build.py` | 只依赖 Python 标准库的结构校验与可选本地 MDL 导出 |
| `source_notes.md` | 官方依据、哈希和解释边界 |
| `validation/reference-contract.json` | 官方表列、键与原始来源类型标注（`source_types`），长度/精度仅供校验 |
| `validation/`、`tests/` | 来源约束、待审项、验证场景及测试 |

使用 Python 3.10 或更新版本，在仓库目录执行：

```bash
python3 build.py
python3 build.py --check
python3 -m unittest discover -s tests -v
# 可选：仅在明确需要独立 MDL 文件时导出
python3 build.py --output /tmp/sap-b1.mdl.json
```

修改 `groups.json`、`models/`、`relationships/`、`views/`、`cubes/` 或 `template.json` 后执行校验，只提交清单和分文件源。当前模板校验仍要求 Views 和 Cubes 为空；新增通用定义时应同步审查其业务范围和校验规则。`build.py` 默认及 `--check` 都只校验，不落盘；只有显式 `--output` 才导出完整 MDL。本地根目录的 `mdl.json` 和 `exports/` 已加入忽略规则，导出文件不是版本维护来源。

tBI 固定一个 Git 提交后读取清单及其声明的 JSON 文件，并在服务端组装、校验完整 MDL。tBI 不执行本仓库的 `build.py` 或其他脚本。本地校验和导出也不访问网络或数据库，不执行 tBI 导入。

## 适用边界

- 标准字段来自官方数据库参考和 DI API 说明；实际表、列、类型与区域配置需要在目标公司库核验。
- 直接来源关系同时保留 `BaseType + BaseEntry + BaseLine`；生产来源和预付款抵扣按各自粒度处理。
- 不包含客户 UDF、自定义 SQL、工作区默认筛选、行级权限、用户或数据源标识。
- 已放行的生产组件与发货估价来源只定义标准键路径；收付款头键、其他估价来源及特殊复制路径仍有待审项，详见 `validation/deferred.json`。
- 工单发料金额、库存估价、历史账龄和核销余额须与目标库及 SAP 标准报表按相同选项验证。结构检查和 SQL 编译不能替代这些验收。

SDK 和 SAP 官方文档的权利归各自权利人所有。本仓库没有附带 SDK 二进制或官方文档全文；官方说明通过链接和来源哈希追溯。


## 分组定义

清单版本 `0.6.1` 使用独立 `groups.json`，由 `template.json` 的 `"groups": "groups.json"` 引用。文件的 `formatVersion: 1` 与清单格式分别维护，每组只包括稳定编码 `name` 和显示名称 `title`。例如：

```json
{
  "formatVersion": 1,
  "groups": [
    {"name": "master_data", "title": "主数据"},
    {"name": "sales", "title": "销售"}
  ]
}
```

归属由模型自身维护，例如 `models/oitm.json` 中的顶层字段：

```json
{"name": "oitm", "group": "master_data"}
```

以上只展示归属片段，模型的其他字段保持完整。视图和分析模型也可使用自己的group字段；分组文件不维护成员列表。导入器校验编码引用后将分类分离，不把这些group字段带入导出的查询MDL。0.6.0旧成员数组仍提供读取兼容；新模板不同时维护两种归属，矛盾声明会被拒绝。旧程序需更新导入器后使用本结构。

本模板101表各归一组：主数据26、销售20、采购22、库存16、生产4、财务10、其他3。基础档案及其配套明细集中到主数据，BOM与工单归生产；凭证、收付款及核销归财务；公司配置、编号系列、每日汇率归其他。分组用于浏览，不限制跨组关系，不进入查询MDL或改变金额定义。0.6.1阶段仅调整分组；当前模型与关系数量以上文0.8.3说明为准。

支持该扩展的tBI会在预览中显示分组和归属变更；首次导入复用工作区同名组，对未分类对象采用模板归属，已有本地分类保留。后续未改现场跟随模板，人工换组、清空或改名后保留现场值；模板不再声明时不删除现场分类。只更新分类无需重新发布语义。旧版tBI没有此管理元数据导入能力，不能只凭文件存在认为实例已分类。

未提供分组文件的旧模板仍可导入；声明但缺失、非法引用、重复归属或路径越界会失败。`modules` 仅说明覆盖模块，不代替分组定义，也不提供模块子集导入。文件不含工作区、连接、权限或现场分组ID。构建会验证分组引用，但导出的完整MDL不包含这些分类信息。

清单版本 `0.6.2` 清理重复来源前缀和仅复述标题的字段说明，简单字段描述留空；销售关键字段补充业务边界，五张销售行表统一使用“毛利计算基价”。官方依据集中维护在 `source_notes.md`，技术字段名、类型、关系与分组保持不变。

## 导入语言

2026-10-27 同步已审阅的对象说明精简：15 个公共表模型和 8 个可选工作区视图的中文说明调整为 220–256 个 Unicode 字符，保留粒度、币种、关联及业务例外；字段、关系、SQL 和默认导入范围不变。英文译文同步核对并保留详细解释，仍有超过 256 字符的对象说明，因此本次不宣称英文导入已适配该长度限制。此提交不导入或发布工作区，也不改写既有发布快照。

默认语言由 `template.json` 的 `language: "zh-CN"` 指定，原始 JSON 继续保存完整中文文案。清单通过 `"translations": {"en": "locales/en.json"}` 声明英文语言包，使用表、字段、关系与分组的稳定编码定位；语言包只包含显示名称和业务说明，不复制表结构、公式或连接条件。

tBI 导入窗口默认采用当前用户语言，允许手动切换；升级沿用上次导入语言。选择默认语言时直接使用原始 JSON，不读取语言包。英文地区语言（如 en-US）可使用 en 包；未提供对应包、文件缺失或个别文案缺译时，使用默认文案。预览展示实际导入语言及整包回退提示。损坏或越界的语言文件会报错，不能作为缺译静默忽略。

导入后实例只保存解析后的单份文案；切换界面语言不会改写既有模型，AI 直接使用已导入的说明。语言包与定义按同一个 Git 提交读取，导入仍经过原有预览、客户修改合并和发布流程。旧版 tBI 会继续读取默认中文定义；使用英文导入需部署支持语言包的导入器。

英文包覆盖当前全部模型、字段、关系和七个分组。`tests/test_locales.py` 检查覆盖、中文残留、技术标识及关键术语；`validation/en-source-text.json` 记录已审阅默认文案的指纹，默认业务说明修改后须同步审阅英文包。运行 `python3 -m unittest discover -s tests -v` 验证，不在导入时在线调用翻译服务。
